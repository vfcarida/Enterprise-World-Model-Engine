# Claim-to-Evidence Registry & Evidence Graph (`ewm-engine` v1.5.0)

> **Purpose**: This registry is the authoritative scientific truth baseline for the Enterprise World Model Engine (`ewm-engine`). Every major public claim in `README.md`, `ROADMAP.md`, `SHOWCASE.md`, `docs/`, and `paper/` is mapped to its exact implementation, automated test suite, benchmark card, primary literature reference, known limitations, and executable verification command. Section 3 provides the navigable **Evidence Graph** (`scientific concept → EWM design decision → source module → test/benchmark → limitation`).

---

## 1. Evidence Taxonomy

Public documentation must never imply an evidence tier stronger than the category recorded below:

| Evidence Category | Definition | Current Claim Count |
| :--- | :--- | :---: |
| `THEORETICAL` | Grounded in peer-reviewed mathematical theorems or formal definitions; implementation enforces the structural assumptions required by the theorem. | 1 |
| `UNIT_VERIFIED` | Verified by deterministic unit and integration tests over fixed inputs and edge cases. | 4 |
| `PROPERTY_VERIFIED` | Verified by randomized property-based testing (Hypothesis) and metamorphic relations across generated state/action spaces. | 3 |
| `CONFORMANCE_VERIFIED` | Verified against a versioned schema and standalone reference oracle suite (`WMIF v1.0`). | 1 |
| `BENCHMARKED` | Evaluated on a seeded, reproducible benchmark card or multi-family suite in `scripts/reproduce.py` / `scripts/run_enterprise_benchmark_suite.py` with recorded numerical tolerances. | 6 |
| `CALIBRATED` | Evaluated with empirical finite-sample coverage diagnostics (TARP, Posterior-SBC, or split-conformal intervals) on synthetic holdout data. | 2 |
| `EXTERNALLY_REPRODUCED` | Independently replicated by unaffiliated third-party researchers in a peer-reviewed replication venue (e.g., ReScience C, MLRC). | **0** *(Not yet externally replicated)* |
| `UNVERIFIED_RESEARCH` | Experimental research prototype or frontier adapter; not yet covered by calibration or conformance gates. | 2 |

## 4. Terminology & Superlative Audit Rules

To prevent scientific overclaiming, all documentation and docstrings in this repository adhere to the following disambiguations:

1. **Sensitivity E-value vs. Safe-Testing e-value**:
   - *Sensitivity E-value* (VanderWeele & Ding, 2017): Minimum risk-ratio confounding strength required to explain away an observational association ($E_{\text{sens}} = RR + \sqrt{RR(RR-1)}$). Implemented in `ewm_engine.experimental.causal.compute_sensitivity_e_value`.
   - *Safe-testing e-value / e-process* (Grünwald et al., 2024; Ramdas et al., 2023): Sequential test random variable satisfying $\mathbb{E}_{H_0}[e_t \mid \mathcal{F}_{t-1}] \le 1$ under optional stopping. Implemented in `ewm_engine.evaluation.uncertainty.SafeTestingEProcess`.
2. **Tolerance-Bounded Conservation vs. "Zero Drift"**:
   - Floating-point simulations must report **tolerance-bounded conservation** ($\le 10^{-12}$) and the **observed maximum residual** (e.g., $4.55 \times 10^{-13}$ in SEIR), never unconditional `"0.000000 drift"`.
3. **Deterministic Difference `(det)` vs. Statistical Significance `*`**:
   - Single-trajectory or zero-variance comparisons must be labeled `(det)` (`status_label="deterministic_difference"`, `is_significant=False`, `is_deterministic=True`), never `*` (`statistically_significant`).
4. **Empirical Calibration Diagnostics vs. Formal Guarantees**:
   - TARP (`Tests of Accuracy with Random Points`, Lemos et al., ICML 2023) using per-instance random reference points $\theta_{r,j}$ and Posterior-SBC are empirical statistical diagnostics over finite simulation ensembles, not formal mathematical proofs of model validity in reality.
5. **In-Model Counterfactuals vs. Real-World Causal Identification**:
   - `world.counterfactual()` computes structural counterfactuals *of the declared simulation model* ($P_{\text{model}}$); real-world validity requires an empirically validated causal graph, calibrated structural equations, and documented `identification_provenance`.
6. **Marginal vs. Conditional Conformal Coverage & 6-Part Uncertainty Taxonomy**:
   - Split-conformal prediction (`SplitConformalInterval`) provides finite-sample **marginal** coverage under exchangeability, not distribution-free conditional coverage $\mathbb{P}(Y \in C(X) \mid X=x)$. Result objects decompose uncertainty into 6 distinct sources (`aleatoric`, `parameter`, `structural_model`, `runtime_context`, `monte_carlo_error`, `model_discrepancy_vs_reality`), explicitly flagging unmeasured sources.
