# ADR-052: Single-Command Scientific Reproduction Orchestrator and Citation Metadata

## Context and Problem Statement

While Enterprise World Model Engine (`ewm-engine`) established software quality gates (strict typing, property testing, and schema validation), research reproducibility required addressing two practical challenges:
1. **The "Rotting Documentation" Pitfall**: Simulation benchmark results frequently degrade into static screenshots or hard-coded figures that drift from underlying code revisions over time.
2. **Local Setup & Worktree Ambiguity**: Reviewers evaluating simulation software need a single deterministic script that executes all reference validation cards, verifies conformance worlds, and distinguishes clean git worktrees (`CERTIFIED_RELEASE`) from modified worktrees (`REPRODUCIBLE_DIRTY_WORKTREE`).

## Considered Options

1. **Status Quo (Static Documentation & Manual CLI Instructions)**:
   - Provide manual `pip install` commands and static screenshots in `docs/results/`.
   - *Rejected*: Prone to documentation drift and lacks cryptographic run-manifest provenance.

2. **Ad-Hoc Individual Benchmark Scripts**:
   - Require users to run separate scripts per validation card without unified manifest verification.
   - *Rejected*: Does not produce a single auditable reproduction manifest.

3. **Single-Command Reproduction Orchestrator + Containerized Environment + `CITATION.cff` (Adopted)**:
   - **Single-Command Orchestrator (`make reproduce` / `scripts/reproduce.py`)**: Re-runs all seven benchmark cards, verifies WMIF reference conformance, checks Structure-of-Arrays (SoA) state tensor bit-identity under the pinned runtime, and emits a structured JSON run-manifest (`reproduction_manifest.json`).
   - **Code-Generated Vector Artifacts**: Re-generates SVG graphics (`ground_truth_overlay.svg`, `calibration_pit.svg`, `multiseed_error_bars.svg`) directly from seeded simulation traces.
   - **Containerized Execution**:
     - **Pinned Docker Container**: OCI image (`Dockerfile`) with `OMP_NUM_THREADS=1` verifying lockfile hashes.
     - **Devcontainer & Notebook**: `.devcontainer/devcontainer.json` and `notebooks/reproduce.ipynb` for interactive inspection.
   - **Repository Software Citation**:
     - Synchronized version metadata across `pyproject.toml`, `CITATION.cff`, and `reproduction_manifest.json` (enforced by `scripts/check_release_truth.py`).

## Decision Outcome

Chosen option: **Option 3 (Single-Command Reproduction Orchestrator + Containerized Environment + `CITATION.cff`)**.

### Architectural Rules & Invariants

1. **Evidence Over Assertion (No Static Screenshots)**:
   - Every figure and metric in `docs/results/` must be generated by code from an explicit seed.
   - Vector SVG artifacts are committed and re-verified during `scripts/reproduce.py`.

2. **Cryptographic Run-Manifest Provenance**:
   - `scripts/reproduce.py` collects host operating system, Python build, NumPy version, BLAS configuration, `uv.lock` SHA-256 hash, git dirty state, and state fingerprints.
   - Output manifest `reproduction_manifest.json` is synced to `docs/results/reproduction_manifest.json`.

3. **Honest Epistemics & Anti-Overclaiming**:
   - Documentation claims only what is implemented, verified, and reproducible in the repository.
   - All literature citations in `docs/REFERENCES.md` are verified against primary literature; unverified identifiers are excluded.

4. **Version & Citation Coherence**:
   - `scripts/check_release_truth.py` verifies version agreement across `pyproject.toml`, `src/ewm_engine/__init__.py`, and `CITATION.cff`.

## Consequences

### Positive
- Reviewers can audit and reproduce every validation card with a single command (`python scripts/reproduce.py`).
- Prevents documentation drift by anchoring gallery cards and visuals to automated run-manifests.

### Negative / Maintenance Overhead
- Updating benchmark figures requires re-running `scripts/reproduce.py` and syncing `reproduction_manifest.json`.
